Bấm một nhánh để chuyển đến toàn bộ file bên trong và đọc giải thích. Các nét nối thể hiện quan hệ bao gồm; luồng request được vẽ riêng ở tab công nghệ.

      Nhánh tự sinh và dữ liệu trên máy

      Các nhánh này được giải thích theo vai trò. Không liệt kê hàng nghìn file thư viện/cache và không đưa nội dung bí mật hay tên upload riêng tư vào sơ đồ.

        Công nghệ nằm ở đâu và làm gì?

        Phiên bản frontend lấy từ package-lock.json; dependency Python lấy từ requirements. Framework, giao thức, database và chương trình chấm có vai trò khác nhau.

        Luồng chạy web và nhận kết quả chấm

        Nhận bài

        ExamPlayer → api.ts → submissions/router.py → source + submission + judge job được ghi nguyên tử. HTTP 202 chỉ có nghĩa server đã nhận bài.

        Chấm và trả kết quả

        worker.py claim job qua job_queue.py, gọi DockerJudge. Kết quả và outbox commit cùng nhau; notifications.py → EventHub → browser. Mất WS thì browser lấy REST snapshot.

        Tính điểm

        Chỉ bài có AC toàn bộ test mới được tính một lần. Mặc định 0/1/2/3/4/5 bài AC → 0/5/7/8/9/10; giảng viên cấu hình ladder và trọng số. Bảng điểm tính ở backend.

        Một API process; worker chấm chạy riêng. Docker Linux Engine cần hoạt động để chấm code. SQLite/private storage dùng cùng máy chủ. Các phiên bản trong sơ đồ mô tả bản source này, không thay thế lockfile.
